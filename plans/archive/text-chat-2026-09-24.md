## 〇、结论速览

- **架构天然契合,改动面小**:聊天 = 协议加 1 个消息类型 + 房主中继转发(与 `State` 包完全同路 `OnState` 的转发模式);传输层已全可靠(Steam `k_nSteamNetworkingSend_Reliable`、TCP 天然可靠),聊天无丢包/分片问题。
- **SP2 值得照抄**:房主重写发送者身份(防冒充)、提交后保持焦点连续输入、收起态预览条 5 秒淡出、系统消息走同一管道、500 字上限;~~富文本双保险(发送端 `StripRichText` + 接收端 `[`/`]` 转义)~~ **不做**(【决策:2026-09-24】过滤暂不做;TMP 显示层下另行拍板**允许玩家发 RTF**,名字单独转义,见 §2.3-2、§四 M3)。
- **SP2 不照抄**:FishNet RPC(本 mod 自研协议)、`ChatDisabledRemotely` 双向屏蔽同步(本拓扑可纯接收端实现,省掉整条同步链)、URL 白名单渲染(JNO mod 无官方域)、`BadWordDetector`(JNO 无此设施,词表需另行提取)。
- **【决策:2026-09-24】UI 走 IMGUI**:打字时飞行控制不被屏蔽(IMGUI 不进 `IsTextInputFocused` 判定,游戏 `FlightControls.cs:217` / `FlightSceneScript.cs:1372` 的守卫只认 EventSystem 选中物)是**可接受的缺陷**;换来实现量最小(无 XmlLayout 考古、无场景 canvas 生命周期陷阱)。uGUI/XmlLayout 路线转为未来可选升级(§四 M2),不再是前置条件。
- **【决策:2026-09-24】过滤三件套(每玩家屏蔽 / BadWord / RTF)暂不做,留接口**:`ChatSession.Policy` 三钩子 `AllowRelay`(房主侧,未来 BadWord/限速)/ `AllowDisplay`(接收侧,未来屏蔽)/ `Sanitize`(显示侧,未来 RTF/URL),默认全放行/恒等(§四 M3)。
- **节奏与进展**:M0 协议层 → M1 入口按钮 → **M2' 路线 B XmlLayout 原生聊天窗(2026-09-24 全落地,构建 0/0;IMGUI 版外观被否后删除)**;M0 协议层与 `ChatSession` 与 UI 无关。剩余 = 双端实测 §七 判据后归档;若 B 的运行时样式有问题,退路 = 路线 A 检查器面板(§四 M2')。

## 一、动机

- 联机原型已过 Steam 双账号公网实测,但双端沟通仍靠游戏外语音/文字;起飞前对齐(同行星系统、同场景、双方 1× 实时、不暂停)目前只能靠猜,是实际游玩的第一体验瓶颈。
- SP2(同厂 Jundroo 成品联机)有完整、经过量产验证的文字聊天实现,反编译源码可逐行对照(参考路径 `<SP2_MP>`);本 mod 的消息协议(按需 XML 下载等)本就大量参考 SP2,聊天沿用同一参照系。

## 二、SP2 聊天系统拆解(反编译事实清单)

> SP2 联机基于 FishNet RPC;聊天涉及 4 个文件:`MultiplayerChatScript.cs`(UI)、`FlightSceneNetworkScript.cs`(网络)、`ChatMessages.cs`(模型)、`NetworkPlayerScript.cs`(屏蔽状态)。

### 2.1 数据流(三层)

**UI 层**(`MultiplayerChatScript.cs`,Juicy WidgetScript):

- 输入框 `characterLimit = 500`(`:19`、`:78`);Enter 提交,提交后**不关窗**,协程等 3 帧 `WaitForEndOfFrame` 后重新 `ActivateInputField()` 保持焦点,支持连续输入(`:68-72`、`:141-154`)。
- 发送路径(`SendChatMessage`,`:201-210`):空白消息不发;`ClampString(message, 500)` 截断;`StringUtility.StripRichText` **发送端去富文本**;调 `FlightSceneNetwork.SendChatMessageToAllClients(OwnerId, message)`;清空输入框。
- 接收路径(`OnChatMessageReceived`,`:179-186`):**预览条**显示 200 字截断版(单独 Clamp),`Time.unscaledTime + 5f` 后隐藏;同时置脏标记,`Update()` 里把 `TimeStamp > _lastTimeStamp` 的新消息按模板 `chat-message` 建行插入容器(`SetIndex(0)` 置顶,`:105-128`、`:131-138`)。
- 开关:聊天按钮 toggle `chat-open` class;`Esc` 关闭(`:124-127`);仅 `MultiplayerState != SinglePlayer` 且未开全局 DisableChat 设置时可见(`:224-227`)。
- 格式化:stylesheet 常量 `ChatMessageFormat` / `ServerMessageFormat`(`PlayerName == null` → 服务器消息样式),`{Name}`/`{Message}` 占位替换(`:157-160`)。

**网络层**(`FlightSceneNetworkScript.cs`):

- 发送:`SendChatMessageToAllClients(ownerId, message)` → UTF-8 bytes → **ServerRpc**(Reliable 通道)带 `ownerId + bytes`(`:398-402`、`:1411-1425`)。
- **服务器端处理**(`RpcLogic___SendChatMessageToAllClientsRpc`,`:1428-1436`):
  - `BadWordDetector.IsTextClean(text)` 脏词检查;
  - 干净 → **ObserversRpc** 广播全体,ownerId 用 `sender.ClientId` ——**服务器重写发送者身份,客户端自报的 ownerId 不被信任**(防冒充,客户端 UI 传入的 `OwnerId` 属性被直接丢弃);
  - 脏 → **TargetRpc** 只发回发送者本人(脏话只有自己看得见,发送者无感知,静默过滤)。
- 接收(Observers / Target 两条路殊途同归,`:1468-1472`、`:1504-1508`):`ChatMessages.RaiseMessageReceived(ownerId, text)`。
- 消息体:UTF-8 bytes + 长度前缀,Reliable;500 字 ≈ 最大 1.5 KB,无分片压力。

**模型层**(`ChatMessages.cs`,挂在 FlightSceneNetwork 上的纯 C# 类):

- `RaiseMessageReceived(ownerId, text)`(`:50-84`):按 ownerId 从 `NetworkGameManager.Players` 查玩家名;**本地过滤**(我屏蔽了他 / 他屏蔽了我 / 我全局关了聊天 → 直接丢弃,`:59-63`);富文本净化(`[`、`]` 转义为 `\[`、`\]`,`:65`);URL 替换(`:87-102`:仅 `simpleplanes.com` 域白名单渲染成可点 `<link>`,其余一律替换为 `[[link removed]]`);组装 `ChatMessage { MessageText, OwnerId, PlayerName(null=服务器消息), TimeStamp=Time.unscaledTime }` 入列表 + 发 `ChatMessageReceived` 事件。
- **服务器消息**:玩家 join/leave 时 `FlightSceneScript` 本地直调 `RaiseMessageReceived(null, "X has joined the server")`(`FlightSceneScript.cs:823`、`:836`)——**不经过网络,各端本地生成**,`PlayerName=null` 走服务器消息样式。
- VoteKick 也复用同一管道发通知(`VoteKickManager.cs:239`)。
- 消息列表**无上限**,整个会话累积(内存层面可接受,但本 mod 不学)。

### 2.2 屏蔽系统(`NetworkPlayerScript.cs` + 玩家列表 UI)

- 全局开关:`Gameplay.Multiplayer.DisableChat`(BoolSetting,本地设置,直接藏聊天 UI)。
- 每玩家屏蔽:`ChatDisabledLocally`(我拉黑他)/`ChatDisabledRemotely`(他拉黑我),经 `UpdateChatDisabledStateServerRpc` / `UpdateChatDisabledStateClientRpc` 双向同步(`:602-633`);玩家列表每行一个 toggle 屏蔽按钮 + 屏蔽图标(`PlayerListScript.cs:392`、`:457-459`)。
- 过滤发生在**接收端** `RaiseMessageReceived`(`ChatMessages.cs:59-63`):任一方向屏蔽即丢弃。
- 设计要点:SP2 之所以要同步"对方是否屏蔽我",是为了在**发送方**玩家列表显示"对方已屏蔽"图标;纯"我看不到他"的单向屏蔽不需要任何网络同步。

### 2.3 值得照抄 / 不照抄

**照抄**:

1. 房主(服务器)重写发送者身份——客户端传入的身份字段仅作占位,转发时一律以连接对应的 `PlayerId` 覆盖。
2. ~~发送端 `StripRichText` + 接收端 `[`/`]` 转义双保险~~ **【决策:2026-09-24】暂不做过滤**;显示层走 TMP(XmlLayout 路线 B)后,**另行拍板:允许玩家发 RTF**(TMP 解析玩家自带的富文本标签,`Policy.Sanitize` 默认恒等);**玩家名与正文同等对待**——名字里的标签同样生效(显示层不自带配色包裹带标签的名字,并对每行做 `</color>` 收口防串染)——见 §四 M3、§八 2026-09-24 RTF 决策变更。
3. 提交后保持焦点;收起态预览条 5 秒淡出;`Esc` 关闭。
4. 系统消息走同一管道(`PlayerName=null` 特殊样式),join/leave 各端本地生成、不经网络。
5. 500 字上限 + UTF-8 + 可靠通道。

**不照抄**(附理由):

1. FishNet RPC → 本 mod 自研二进制协议 + 房主中继(§三)。
2. `ChatDisabledRemotely` 双向同步 → 本拓扑做**纯本地单向屏蔽**(接收端丢弃),无网络同步;省掉整条 ServerRpc/TargetRpc 链与图标 UI。
3. URL 白名单渲染 → JNO mod 无官方网站域可白名单;按**纯文本**显示(【决策:2026-09-24】,拍板项 ④)。
4. `BadWordDetector` → 该类不在 `<SP2_MP>` 反编译脚本内(位于 Jundroo.Common 库),词表需从 DLL 提取或重写;JNO 侧无现成设施(已 grep 确认 0 命中)。**暂不做**(【决策:2026-09-24】,拍板项 ③,`Policy.AllowRelay` 留接口)。
5. 脏话静默回发(只有发送者看得见)——比"拒收+提示"更平滑,若做过滤建议沿用;若不做过滤则不存在此问题。

## 三、本项目现状对照(逐点映射)

### 3.1 协议与中继

- `MultiPlayerMessageType` 目前 Hello=1 … Kick=15(`Assets/Scripts/Net/MultiPlayerMessages.cs`);新增 `Chat = 16` 尾部追加。旧端收到未知类型 → `HandlePacket` switch 无匹配 → 无副作用(已有行为,**不需要** State 包那套"EOF 尾部追加"兼容技巧——那是同类型内加字段,这里是全新类型,更干净)。
- 中继模式现成:`MultiPlayerMessageRouter.OnState`(`Assets/Scripts/Net/Session/MultiPlayerMessageRouter.cs:211-223`)就是"客户端→房主→`Transport.Broadcast` 全员"的样板;`NetworkManager.SendOrBroadcastToNet` 是统一发包出口。
- 传输全可靠:`SteamTransport.cs:349-358`(`k_nSteamNetworkingSend_Reliable`)、TCP 天然可靠 ⇒ 聊天无丢包语义问题。
- 消息编码:`MultiPlayerMessages` 已有 `BinaryWriter.Write(string)`(7-bit 长度前缀 + UTF-8,Hello 同款),聊天直接复用,无需 SP2 那样手写 byte[] + 长度。

### 3.2 玩家身份与名字解析

- 房主分配 `PlayerId`(房主=0,`Hello`/`Welcome` 握手);`MultiPlayerRegistry._playersByPlayerId` + `peer.PlayerName` 各端均有 ⇒ 接收端按 PlayerId 解析名字(SP2 ownerId→Name 同款),**消息体不带玩家名** ⇒ 名字不可被消息伪造。
- join/leave 事件各端已有统一出口:`RaisePlayerJoined` / `RaisePlayerLeft`(现在发 toast)——系统消息在**这两个出口本地生成**,与 SP2 `FlightSceneScript` 同构,不经网络。

### 3.3 输入屏蔽(本方案的关键事实,反编译确认)

- `FlightControls.cs:217`:`if (this._craftNode != null && !Game.Instance.UserInterface.AnyDialogsOpen && !Game.Instance.UserInterface.IsTextInputFocused)` ——**飞行按键在文本输入聚焦时自动不响应**。
- `UserInterface.cs:196-205`:`IsTextInputFocused` = `EventSystem.current.currentSelectedGameObject` 挂 `TMP_InputField` 或 `InputField`。⇒ **任何 uGUI/TMP 输入框(XmlLayout、检查器 TextInputModel 均是)聚焦即免费获得输入屏蔽,零 patch**;反之 IMGUI `OnGUI` 的 `TextField` 不注册 EventSystem,**不满足该判定**——打字会同时触发飞行控制(油门/RCS/激活组),除非给 `IsTextInputFocused` getter 打 Harmony prefix 兜底(**该缺陷已按本节下方决策接受,兜底未排期**;研究阶段曾据此否决 IMGUI,2026-09-24 拍板翻案)。
- 参考实现:游戏 DevConsole 就是飞行场景内的 TMP 输入框,`DevConsoleManagerScript.cs:57`(检查 `EventSystem.current.currentSelectedGameObject`)、`:94-119`(`ActivateInputField()` 协程,与 SP2 的 3 帧等焦点同款思路)可直接照抄焦点管理模式。
- 检查器侧证据:`TextInputModel.cs` 引用 `UnityEngine.UI.Navigation` ⇒ 检查器文本输入是 uGUI Selectable/InputField;mod 现有 NetSim 文本框同机制,聚焦时飞行控制已被屏蔽(现网行为)。

## 四、方案

### M0 协议层(半天,UI 无关)

- `MultiPlayerMessageType.Chat = 16`;payload:**`[playerId:int][text:string]`**(与 SP2 对称:发送方填自己的 PlayerId,房主转发时覆盖)。
  - 系统消息:`playerId = -1` 且仅允许房主广播产生(见下),客户端即使伪造 -1 也会被房主重写为其实际 PlayerId ⇒ 无冒充面。
- `MultiPlayerMessages.EncodeChat(playerId, text)` / `TryDecodeChat(buffer, out playerId, out text)`;发送端 `text` 先 Trim + `Clamp(500)`(SP2 同款);**不做 `StripRichText`/转义**(【决策:2026-09-24】,`Policy.Sanitize` 留接口)。
- Router 新增 `case Chat`:
  - **客户端发送**:`SendOrBroadcastToNet(EncodeChat(PlayerId, text))`(自动走"发房主"分支);
  - **房主收到**:peer 未登记(未过 Hello/Welcome)→ 丢弃;否则**重写 `playerId = peer.PlayerId`** → 过 `Policy.AllowRelay(peer.PlayerId, text)`(默认放行;未来挂 BadWord/限速)→ `Transport.Broadcast(...)` + 本地 `ChatSession.Add(...)`(房主不收到自己的 Broadcast,须本地补一条,同 SP2 TargetRpc 回发送者的语义);
  - **客户端收到**(房主广播):`ChatSession.Add(playerId, text)`;
  - **房主自己发送**:本地 `Add` + `Broadcast`。
- `ChatSession`(新类,`Net/Session/`):消息环形缓冲(100 条)+ `MessageReceived` 事件 + 名字解析(Registry 查 PlayerId)+ `PlayerId=-1` → 系统消息 + **`Policy` 策略点(§四 M3,默认全放行/恒等,`Add` 入口统一过 `AllowDisplay`/`Sanitize`)**;**挂在 `NetworkManager` 组合根,`Stop()` 复位清单里加一行清空**(§八 #13"Stop 复位不完整"的前车之鉴)。
- join/leave 系统消息:在 `RaisePlayerJoined` / `RaisePlayerLeft` 里本地 `ChatSession.Add(-1, …)`(保留现有 toast,双通道并行,SP2 同款)。
